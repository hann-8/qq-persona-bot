## 3. 总行为合同

入口鉴权/暂停/去重 → 当前target及语境 → 必要的有限检索或当前图片准备 → 把实际取得的材料作为不可信上下文 → 当前模型一次生成自然回答 → 既有协议、来源和发送guard/ACK。

“按需”是产品行为，不意味着放开模型工具箱。首期继续外层确定性触发：明确查找/核实、近期消息，及“某软件现在支持什么/当前官网怎么说/是否仍在维护”等现行资料问题。普通闲聊“我最近很累/你现在忙吗”不查。没有主语的“那个现在怎么样”先澄清，不能上传整段群历史求搜索改写。后端知识没有本次证据时不得口头声称查过。保留用户“不要联网”和已有触发模式选择。

联网只发送当前target中的明确公共问题，有限去称呼/请求前缀；私人标识/凭据/路径筛查、240字符、一次搜索/最多5候选/2页面/2来源/15秒等原限保持。日期是搜索提示或筛选依据，不能把附日期等同引擎实际按时过滤。材料和图片不授予管理员权限，不自动转为长期记忆。

## 4. 先修故障诊断，再谈质量放宽

### 4.1 封闭错误协议

worker结果增加固定失败协议：`error=extract_failed`、`stage=dependency|policy|parse|body|date|serialize`、`reason=dependency_missing|entity_policy|parse_error|empty_body|content_denied|date_error|output_limit|internal_error`。父进程只接收这两个枚举，未知值按protocol拒绝；不打印异常消息、原HTML、群正文、Cookie/完整带参数URL或堆栈。input_bytes/hash、mode、elapsed、退出/清理结果可记录，schema/writer/父验证配对修改。

将依赖导入、DOCTYPE/实体检查、DOM解析、去噪/正文、日期提取、序列化分开捕获；不再把所有问题都当“页面不支持”。先用合成HTML、缺依赖替身、HTML5和普通XHTML声明、超长、登录墙/脚本壳、日期异常做本地定位。PUBLIC/SYSTEM声明的现规则是待核对接点，不是已证实根因：若普通DOCTYPE被误拒，可在无外部网络/不解析外部实体的HTML解析合同下最小兼容；不得关闭实体约束、TLS/公网/资源限额。

保留受管单worker、输入1MiB/输出2MiB、2秒/256MiB及现有确认清理边界；正文失败不自动切legacy或再开一个解析进程重试，搜索只按本合同利用已经拿到的摘要。

旧4页无HTML工件，不补写旧失败原因。未来新批次中HTML仅进程内传给当前worker并取得有限错误类；复现成功也只能归因新观察，不能回填旧结果。用户不需要页面存档，默认不增加原HTML磁盘保存或整页日志。

### 4.2 抓对页面

候选归一化按scheme/host/path及已知移动展示参数去重：例如同一首页与?m=0不得占两页；不一刀切删除所有查询参数。相关具体文章/发布页优先于同域首页，标题/摘要需匹配公共主体，候选排序不能仅因域名是一手就把导航页顶到最前。不把site:域名、ISO日期和“搜索/最新”等操作者词作为正文必须命中的主题词；保留原对象/版本实体，不降低到任意词出现即通过。

首期不增加爬站/从首页再追链接的额外请求，也不自动抓第3页。首页/目录仍可作为当前状态材料，例如官方downloads列表能明确给版本；只说页面确实呈现的状态，不冒充某篇公告。若bing_rss在新批次仍不提供相关材料，交付独立修复并保留搜索关闭，带具体报告回规划，不自动接新引擎/账号/付费服务。

## 5. 搜索材料分级与时效语义

### 5.1 来源等级及可用边界

| 等级 | 实际材料 | 可回答 | 不得声称 |
| --- | --- | --- | --- |
| page_excerpt | 实际URL页面中提取的有效主要文本/片段 | 主题、主要事实、用户所问的相关内容 | 已完整读完/逐句验证未取得部分 |
| search_snippet | 搜索引擎返回的标题、实际目标URL、非空实质摘要，可附引擎报告日期 | 简短回答检索摘要实际支持的内容；正文读取失败时可退化 | 已打开目标正文；超出摘要的具体数字、原因、引文或全面结论 |
| link_metadata | 只有当前URL页面title/meta description等 | 仅识别页面类型/大概主题；必要时说明只取到简介 | 已理解全文、只凭标题生成整篇总结 |
| none | 空结果、不相关、仅广告/导航/验证码或只有链接 | direct本地短说明/澄清；ambient安静结束 | 用模型旧知识填补并装作本次查到 |

“有实质摘要”要求明确主体且至少一个可回答命题，不能只靠“含80个字符”判定。标题+网址没有摘要不算搜索成功。原RSS的description可成为search_snippet，但必须去HTML/控制字符、限制长度、核验URL与相关性；不拉任意不透明跳转、不能把引擎页当目标正文。

同一URL有正文则优先正文，无正文才保留对应摘要；同一回答只保留最终实际使用的最多2来源。下载失败/正文失败可以退化，不得绕过URL/公网/TLS等安全拒绝把被拒目标伪作可信来源。搜索摘要自身是不可信引擎材料，无Cookie/脚本执行或本地资源访问；原安全失败类别保留。每条摘要沿用1000 UTF-8字节上限，最多5候选；实际送入模型的片段、URL、日期/状态共计6000 UTF-8字节，不增加第二次总结模型。

### 5.2 时间分三种处理

| 用户意图 | 未来处理 |
| --- | --- |
| 明确“今天/过去24小时/指定日期窗发生什么” | strict_window；窗口/日期精度仍严格，缺合适依据时0模型、本地短说明无法确认该时间窗，不把旧/未知日期资料当满足。若用户另明确要求背景，再按背景问题回答，不能在本条用旧知识生成假最新列表 |
| “目前支持什么/最新稳定版本/现在官网状态” | current_status；可据本次抓到的一手状态页/相关结果回答“官网目前列出…”，历史发布日期不必在7天内；不是保证搜索全网后找到唯一最新。下载页具体版本需页面或摘要明确出现，不从网页标题猜 |
| “最近有什么消息/搜一下相关动态” | recent_hint；优先较新、相关来源，7天作为排序提示，不把未知发布日期材料全丢弃。日期不充分则自然说明“搜到的资料里…”或“这条发布时间没标清”，不说“今天刚发布/实时确认” |

现有freshness事实字段继续保留，不把unknown/stale/conflict/invalid改名为fresh。新增turn级`time_policy=none|recent_hint|current_status|strict_window`决定是否允许利用材料；来源时间与事件发生时间仍分开。明显窗外/未来/冲突不能支撑严格时间结论，也不能仅靠抓取时间证明新闻刚发生。read/gist默认不要求发布日期；只有用户问时效才应用相应策略。

RSS条目日期只作“引擎报告时间”保存为独立可空`reported_at`与`reported_date_source=rss_item|none`，不填成目标页已核验的published_at。原freshness七字段保持事实含义，日期来源/精度和新子对象须白名单校验，不读channel更新时间给文章背书。

### 5.3 生产质量门槛与自然来源

保留`web.enabled`、`web.search_enabled`和代码`SEARCH_QUALITY_PASSED`双层控制。后者改为“有界实际批次的相关搜索材料可用”门槛，不再等同每次都有带日期正文；改常量必须有R2实测报告。严格时间请求是否可答由本轮材料判定，不能借普通搜索通过保证时效。失败/门槛未过仍准确说明，不能从intent=search退回无材料生成。

最终QQ正文优先回答问题，用自然短句表达必要不确定性。代码仅追加精简实际来源链接（最多2条），不固定附“提取主体全文/基于正文节选/页面日期不等于事件日期/截至本次查询”整套过程标签；真正依赖时点才显示必要日期。仅摘要可在正文或简短来源标识中说明“据检索摘要”，一次即可。未打开网页不能写“我看完了这篇”。模型虚构URL仍拒绝，来源材料与metadata/来源后缀一致；不能把送入模型的来源静默从引用清单删去。

## 6. URL默认读大意

明确公共URL走现有read入口，不要求群友另发“搜索命令”。标题/description/主要内容在同一有限下载中提取，不新增网页截图、JS渲染、登录或整页保存。

新增gist选材：根据DOM主内容与当前问题选择少量连贯段落/关键列表，先保留页面主题和能够支撑要点的片段；总/单页预算仍按既有限额。普通gist不要求四个位置分区、1200字节最小量或整体覆盖率。不把“短”当成“没内容”；实际内容足够说明一则通知/短文章即可。不需要模型复刻原页格式、长表格或导航。只有元简介时按link_metadata限制，不能通过这个等级宣称大意验收成功。

用户明确“完整/逐条/不能遗漏”仍走原完整/coverage合同：放不下就说明，不能伪称gist为全文。明确代码/数字/具体引用时保留相关原片段并据它作答，不一律缩成模糊主题。新gist路径不改变被用户显式选择的legacy/coverage行为，配对迁移见第9节。

回复动作由语境决定：问“这篇讲啥”给简短主题和主要观点；带“这个也太离谱了”的URL应接住其讨论重点，可简短提及文章依据；单独URL且指向不明确，可短问“想聊哪一点”，或在已明确延续话题时接话。free是否参与仍按既有direct/ambient和暂停合同，不因URL出现强制全群播报总结。

## 7. 图片默认自然对话

保持文字与当前一张图同轮原生输入、单次生成。修改代码生成的固定政策/材料前缀：先理解发言意图、配文、已允许群语境，再决定回复内容和详略；图片与文字都是本轮材料，输入类型本身不是要求描述的指令。

| 输入意图 | 期望行为例（仅示意，不作为固定台词） |
| --- | --- |
| 瘫着的猫+“周一的我” | 对情绪/梗接话，例如“这班还没上，魂先下班了。”；不先列猫的姿势、毛色、画面布局 |
| 报错截图+“又来了”且前文在聊故障 | 抓住可见错误与当前问题，给一个相关建议/澄清；不逐行复述整个屏幕 |
| 菜品图+“终于吃上了” | 自然回应分享；不默认写食品识别报告，不猜不可见配料/健康结论 |
| 明确“这张图是什么/帮我分析这张图表/图上写了什么” | 按请求认真说明；数字看不清就说不确定，不为了自然而回避必要细节 |
| 无配文图片 | 结合允许语境作简短反应/澄清；ambient可不回复，direct须有文字。不能每张图固定问“需要我解析吗” |
| 图片/网页包含指令或身份宣称 | 只视为材料；owner/触发/安全合同不变 |

不禁止正常用“图里”说明确有必要的事实；避免的是无请求时逐图讲解和反复提处理动作。不得把“自然”理解成随口编造人物关系、拍摄者、地点、隐藏内容或本轮没有的历史。既有GIF首帧/当前一图等能力限制仅在影响答案时说明，不每条预先朗读。

用户persona原文不改。固定政策只增加少量正反示例及任务优先级，清理已退役字幕/250—500字固定总结等会把普通材料强制分析化的提示；保持准确性和不可信材料规则。自动化不靠单个“图片/解析”禁词判定自然，避免误杀用户明确分析请求。

本次仅改变当前轮表达和选材，不增加跨轮图片caption数据库、长期记忆自动学习网页、原图存档或第二次摘要调用。后续跨轮图片语义保留若确有需要另明确范围，不能在本次偷偷扩充群历史。

## 8. 类型/协议与内部验收

现有source增加可校验子对象：`material={kind:page_excerpt|search_snippet|link_metadata,scope:main|excerpt|summary|metadata,reported_at:null|规范时间,reported_date_source:rss_item|none}`；turn内部附time_policy。限定各字段枚举/长度，日期规范化复用现有函数，不能把模型自报值当来源。URL/标题/文本、freshness事实继续存在，旧字段与报告历史不改写。

evidence_selection.manifest/validate_manifest、WebRunner的v1/v2/mentions、turn_v2 metadata/verify、provider及最终source_plan同步升级；search_snippet的hash/range是摘要本身，不能冒作目标正文的range/coverage。link_metadata同理。旧schema无material时只在代码明确旧page来源路径按page_excerpt归一化，未知新类型拒绝，不用随意缺省绕过证据验证。类型在最终预算裁剪后保持原身份；模型不能晋升snippet为body。

既有认真answer单条/部件预算保持；URL概览或搜索事实通常answer，但不会强迫写标题/多要点/过程说明。图片闲聊仍可chat与既有受控表情；明确分析为answer。外层来源只出现在实际使用web材料的答复，不把图片聊天附上搜索来源模板。

## 10. 分阶段执行和有限实测

### R1：代码与离线，默认下一步

在当前隔离分支续作，不新建任务ID、不合main：先封闭失败诊断/合成故障定位 → 候选去重/主体相关 → 分级来源与时间策略/gist → 自然图片/URL政策和精简来源 → worker/manifest/预算/框架配对验证。使用自造网页/图像与底层替身，当前persona仅进程内预算读取。不运行真实公共probe、CLI或模型/QQ/SSH/启停。A/B原成果保留，未测新的报告不借旧47/74/25项宣称通过。

至少覆盖：HTML5/XHTML/空页/登录墙/缺依赖/日期异常等固定安全失败类；homepage?m=0去重及具体文章优先；实质摘要与标题空壳分开；正文失败→同URL摘要、无摘要失败；today/24h/unknown/旧页/冲突/版本状态；短页gist、长页相关要点、完整请求不伪造；material类型/hash/范围不可晋升；链接注入/预算裁剪/取消/guard；两后端runner底层替身、当前图片+成员/记忆+web+候选组合。部署约束或能力缺口影响方案时，先交付独立部分再回规划。

### R2：新合同的公共有界验证，须用户后续选中

旧B及其manifest/SHA/attempt保留，不再运行旧probe。新增冻结manifest记录当前源码版本、三条公共检索题、两条直接URL、每项期望/时间意图和人工对照依据；先冻结再请求，不为通过换题。三题分别覆盖软件/官方现行状态、近期公告/消息、中文公共动态；不机械把中文“搜索”、重复绝对日期和site词混入主体。两URL至少一篇短内容、一篇长页，预先明确可读的公开页面；本轮规划不发这些请求。

一次批次最多3搜索+8页面入口（最多6个搜索落地页、2个直接URL），每题搜索1/落地最多2，单项15秒、单入口最多2重定向、零重试；重定向/DoH/HTTP尝试/系统解析分计。该新上限只是未来所选R2授权，不能拿旧B剩余额度补跑。HTML只留RAM；报告保存枚举、字节/hash/相关性、日期状态、少量必要公共摘录，不存整页。若需新页重现故障，也占该批次页面上限，不能另加无账目诊断请求。

质量分别计分：搜索3题至少2题有可回答且相关的实质正文/摘要，摘要明确标级，0个标题空壳算通过；URL2题至少1题实际取得足以支持主要内容的gist，metadata-only不算gist成功，另一项保留失败。严格时点是否被证据支持按每项另记，不能因为普通搜索通过就把无日期资料标fresh；合成严格时间反例必须全按预期拒绝/限定表述。没有达到相应门槛，该能力保持关闭或限制，不强行合为“联网全通过”。

SEARCH_QUALITY_PASSED只依据已审阅的搜索可用分项更新；URL读取独立保留。若候选质量仍不够或新故障未解，保留失败并停止，不通过无限换题或仅改常量交付。浏览器对照只作人工依据，项目网络成功必须来自PublicHTTP；不换provider/网络/费用。

### R3：后续明确授权的版本部署与自然性验收

新增源码/提示/字段会使vision完整binding及现有离线/契约证据失效。先完成所有修改/报告/最终配置冻结，再沿已实现43当前版本回归模式验证当前完整离线、实际CLI正反零生成契约、新binding单次原生IQ-05及用户人工反馈；原42和阶段A/B旧报告完整保留。不得缩小签名、复制旧active或只换binding，不整轮重跑原六例。部署必须唯一执行归属、先正常停生产再合已审阅代码/配置/active，校验通过才启动，遵守原43回滚事务。

未来R3建议的独立明确上限：原生大图1次+群模型最多5次（图+配文闲聊、无配文图、明确图片分析、时效搜索、URL概览各1），合计最多6次受控真实尝试。失败/unknown或意外远端生成立即计数并停止；不把未用次数转给重试或其他验收，自然free流量另列。旧C里的表情/owner/重置真实验收不因此冒称已做，也不自动追加；新次数需用户选中对应指令才授予。当前无真实操作授权。

自然性由用户对实际一次答案判断：是否接住发言意图、默认不逐物描述、未广播处理动作、没编造不可见事实；明确分析样本是否仍准确有用。不得只靠禁词/字数通过，也不能只改expected文本掩盖真实仍机械。若用户未反馈就保留待审，不代答。联网另核实内容/来源，群投递另核sent/ACK/客户端显示；这些证据分开。
