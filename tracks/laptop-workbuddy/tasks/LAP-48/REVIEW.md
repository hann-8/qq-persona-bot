## 1. 用QQ号标识群友，不再给每条记忆编号

文件按QQ号组织，名字单独显示；改名不会换人，同名也不会混淆。合成示例：

~~~json
{
  "schema_version": 3,
  "group": ["群里约好周五晚上联机。"],
  "members": {
    "123456789": {
      "name": "小青",
      "memory": [
        "喜欢清茶，不喜欢太甜的饮料。",
        "希望被叫小青。"
      ]
    },
    "987654321": {
      "name": "小蓝",
      "memory": ["最近在学吉他。"]
    }
  },
  "unassigned": [],
  "_meta": {"说明": "程序使用的保存版本、请求去重和旧身份关联；不交给模型"}
}
~~~

取消原方案的mN成员别名、rN记录编号和逐条编辑接口。模型要修改或忘记一个偏好时，回写该成员整理后的一整块memory；程序无需准确定位某一条。没有改动的成员不用重写，避免每次抄整群。group和暂未关联的旧内容也按整块更新。

磁盘文件缩进方便人看；模型读取紧凑编码的全文、QQ号和名字，不读_meta。继续自主记忆、合并、整理和遗忘，不减少全文范围、不加关键词筛选，也不把群记忆主动带进搜索查询。

**重复处理：** 同一成员或同一块内完全相同的文字，保存时可去掉重复副本；不会跨成员去重，因为两个人可以有相同喜好。意思相近、表述不同的重复由现有Planner看全文后合并，保留时间、变化和不确定性。不新增向量库、额外模型调用或相似度门槛；不能保证语义去重百分之百准确，也不作为上线门槛。

**旧数据：** 旧哈希不能反推出QQ号。用已有本机身份和旧算法匹配，能关联的直接迁移；本轮只读核对仍有一位历史成员暂时无法关联。其内容保留在unassigned，旧关联放_meta，后续真实身份匹配后再归入QQ号下；不猜账号、不删记忆，也不阻塞其他功能。

## 2. 联网采用薄适配，去掉重复的防御性校验

天气样例：19:27:03收到问题，19:27:12因tool_plan_missing被本地拒绝，随后连带native_ready；19:27:39的天气答复属于后续消息触发的另一任务。这次不是总运行期限超时的证据。

直接复用CLI官方WebSearch/WebFetch和tool.call。删除第二份计划匹配、逐步历史完全重演、前缀完全相同和阶段必须按固定顺序齐全等前提；正常流式、并行、网页内嵌摘要都可以工作。网站报错、重定向或一次读取失败作为工具结果交模型处理，不让一页失败拖垮整次问答，也不统一说“接不上模型”。

保留两工具范围、实际输入容量和可调整运行预算。现有8次工具执行作为预算，耗尽时交模型用已有材料收尾，不把预算提示当越权。取消原生联网固定10步的额外拒绝；旧配置字段兼容但不再执行这道门槛。长结果按现有容量截取，不另加词表、域名评分、来源凑数或质量审批。

整项运行改为**180秒，两阶段共享**，表达预留30秒；按现有清理额度，Planner默认约145秒。外层等待随配置推导，当前排队30＋运行180＋余量25＝**235秒**。任务在工作时不提前发失败；真实连接/账号故障立即说明。本地联网适配错误与后端不可用区分。沿用一次任务，不自动整项重跑或换模型、账号。
