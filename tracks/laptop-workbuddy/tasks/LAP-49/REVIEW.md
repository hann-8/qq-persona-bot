# LAP-49 评审：自然接话，保留大肥鱼的味道

已于2026-11-07确认并实施：以LAP-47短人设为底，补回大肥鱼特征和完整颜文字库，把回复的具体说法留给当下语境。Planner→Replyer继续沿用。用户指定当前会话实施并明确不要启动bot，已完成且保持停止，见[实施结果](RESULT.md)。

先看 [完整候选人设](PERSONA_DRAFT.md)：这份正文就是拟替换`config/persona.md`的内容。用户已确认角色味道并直接授权当前会话实施，原样部署，未另行派发medium。[技术证据与交接](HANDOFF.md)。

## 改什么，为什么

你的体验是：此前短稿更像真人，但角色辨识度丢得太多；恢复完整版后又显得生硬。这个比较支持先做小范围人设调整，但不能把全部变化因果都归给提示词。

替换前完整版约17.6KB，既有“每条1～3个颜文字”“固定否认→找理由→妥协”，也有固定任务开场、夸奖反应和收尾模板。源码会把整篇材料送入两个阶段，连开发者使用说明也没有剔除。它们容易把发言拉向重复表演。此次只替换这一份角色材料即可，阶段协议和拼接代码保持。

| 保留的大肥鱼特征 | 放宽的表达方式 |
| --- | --- |
| 蓝鲸/鲸鱼娘形象、聪明馋懒、嘴硬心软 | 性格随当前对话表现，不规定反应先后 |
| 本鱼/鱼鱼/鱼片、吃米、泡水、冒泡、煮饭等梗 | 合适时随口用，普通接话也允许平淡 |
| 原有15组完整颜文字武器库 | 按情绪自由选，不设每条或每几条配额 |
| 认真时可靠、事实和代码准确、身份照实说 | 闲聊顺着说，吐槽可只接吐槽，真正提问才展开 |

删去开发者说明、元数据、重复的行为/安全清单、情绪状态机、长篇示例与自查表。宿主已有的真实权限、能力、记忆和输出协议继续由原系统提示与代码负责。候选稿仍保留“不虚构现实经历或已执行结果”等必要表达底线；角色梗不扩展能力。

例如，“你是不是又胖了”可以接“……这叫知识储备。”；“今天不想干活”可以接“巧了，本鱼已经沉底了 (´-ω-)zzZ”。这些只是人工说明表达空间，不是实际模型样本，也不作为运行提示里的固定台词。

## 范围、代价与生效

本项业务改动仅`config/persona.md`。没有新增配置项、开关、模型调用、评审模型、关键词分流或新后端。现有模型、账号、思考、温度、工具/时间/输出预算、触发范围、识图、记忆和受控表情保持实施前实值。沉默仍一业务阶段，发言仍至多Planner→Replyer两业务阶段；Planner内部工具往返不能据此算成严格只有两次上游请求。

两阶段都接收角色材料，缩短文件会减少相应输入文本；真实token、用量、价格和延迟取决于实际请求，不承诺固定降幅。完整颜文字库会比514字旧短稿多占一些输入，换取明确的角色素材。对比以文档检查的UTF-8字节为准，不将字节当token。

启动时从原路径加载，不另建运行人设入口。人设在现有识图技术签名内，实施时按既有离线检查、CLI零生成配对和受管部署完成一次；保留识图启用和原质量待用户实测状态。人设变化会更新原会话版本，短期上下文按既有机制刷新；长期记忆、图库和状态数据不迁移或清空。

本根QQ与已接入的微信路由共用这份角色材料，表达会同时受影响；不改独立`E:/CodexWS/WeChatbot`项目，也不单独操作其进程。

## 必要验证、风险和回滚

规划只查文档链接、实际候选内容、原15组素材是否完整保留，以及Git差异。实施只核对批准正文、UTF-8和两阶段拼接/预算，复用既有必要离线与零生成配对，部署后核对实际加载和原能力；不写逐句字符串测试，不重跑历史大矩阵，也不主动调用真实模型、搜索或发群测试消息。

最大的未验证项仍是自然群聊效果：完整素材库也可能让颜文字偏多，缩短指令也可能让角色感时强时弱。既有上下文和模型本身同样影响输出，不能保证只改人设就稳定达到此前感受。部署后由你自然群测，再根据具体回复调整正文，不扩建风格打分或自动改写链。

实施前把当时实际人设及必要技术配对精确备份到忽略的`state`目录；不把私有配置/备份提交。回滚只恢复这次人设和匹配的技术配对，必要时按当前源码重新配对，再受管重启；保持Planner→Replyer，不整目录覆盖后续配置，不回滚记忆或图库。本根短期`codex/`分支实施，交付回main、commit/push核对并清理已合入临时分支。规划文档已在main交付；本次按用户授权在短期分支实施后回main，保留用户未跟踪文件，完成后保持停止。
