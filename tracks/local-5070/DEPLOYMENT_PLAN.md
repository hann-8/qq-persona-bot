## 1. 目标与拓扑

把模型推理换成PC本地，不再依赖WorkBuddy账号；保留个人QQ、指定群真实@、人设、上下文隔离、B站字幕/本地ASR。

```text
个人QQ → PC NapCat → 同一strict gate → PC AstrBot
                                     ├→ 本地Ollama文本模型
                                     └→ 同一B站插件 → 字幕/本地ASR → Ollama总结
```

默认把全套bot部署在PC，笔记本保留可启动的WorkBuddy模式。同一个QQ账号不同时启动两份活动回复链路；切换时先停旧实例，再在新机器扫码登录。两条线“均部署”不意味着同账号两套同时发群消息。若用户要求同时在线，需另一个QQ账号或统一单入口切换模型，先明确该需求。

可选后续拓扑：QQ入口仍在笔记本，PC只提供推理服务。这需要两台机器都在线、同网可达和受鉴权的局域网模型代理；不作为首个默认，避免笔记本睡眠导致PC模型虽然在线bot仍下线。

## 2. 周末开始前一次盘点

1. PC操作系统、RAM、可用磁盘、RTX5070实际显存和驱动、GPU是否被游戏/其他服务占用。
2. PC可否下载Ollama模型和Whisper模型、B站网络/登录是否正常。
3. 是否继续使用同一QQ号，哪些测试群、管理员、人设要同步。
4. 接电、合盖/睡眠、开机登录等运行条件；不擅自改电源策略。

Windows10/11原生为默认预案；若PC是Linux，调整启动/安装脚本即可，消息/HTTP/视频契约不能随之改变。不要按笔记本Python/路径推断PC条件。

## 3. 模型选择与资源预算

首个可靠基线：`qwen3:8b`，Q4_K_M，Ollama官方模型页约5.2GB权重。它是方便验证和回退的起点，不声称是周末时最新/最强型号。

初始单模型、单并发、8K上下文；先用文本模型，不同时加载视觉模型。权重+KV缓存+运行时显存必须以`nvidia-smi`和`ollama ps`实测，不能用“权重5.2GB”推出峰值必然小于12GB。

若候选更新版本在中文聊天/人设/摘要测试中明显更好且满足资源预算，可A/B替换；变更须记录model tag、digest、量化和参数。14B/32B与大MoE不作为12GB首装默认，避免只看激活参数忽略总权重。

若模型启用推理过程，按所装Ollama/模型的官方方式关闭或限制思考，并验证用户最终只见答案；不要只通过正则删`<think>`假装减少了推理开销。

本地上下文预算须比笔记本更紧：聊天先4轮，正文分段先约3000字，总输入预估约6000字以内并为输出留余量。字数不等于token数，以可用tokenizer或实测结果约束到8K上下文。不能把笔记本24K字请求上限原样用于8K模型。

ASR先沿用CPU/int8，避免和LLM争显存。若需要GPU ASR，核对当前faster-whisper/CTranslate2/CUDA/cuDNN与RTX50系列兼容，单独验收；不一边加载多个大模型一边排查OOM。

## 4. 分阶段实施

### L0：先验证PC模型

- 官方渠道安装Ollama，记录版本、driver和model digest；模型缓存放空间足够的盘。
- 验证`nvidia-smi`识别RTX5070，Ollama确实GPU推理，没有未察觉的全CPU回退。
- 运行3类样本：短聊天、多轮随机口令、固定字幕摘要。记录冷启动、热启动总耗时、峰值显存、失败情况；不预先承诺tokens/s。
- 若OOM：先降上下文/并发，再选择更小量化或模型；不擅自加付费云端回退。

### L1：复用部署工件

- 复制自有代码、人设、无密模板、版本清单与插件fork；不复制QQ登录目录/WorkBuddy认证数据。
- 需要迁移历史时单独备份并确认，默认新实例空历史；避免在PC把笔记本测试会话当作正式用户记忆。
- 独立生成PC本地OneBot与网关token，更新本地路径，重建Python环境。
- 复用同一strict gate和群白名单，不能因“本地模型”省略触发规则。

### L2：切换AstrBot模型端点

- 默认继续通用OpenAI provider，指向已验证的`http://127.0.0.1:11434/v1`，模型填写实际安装tag。
- `modalities=["text"]`、`custom_extra_body={}`、非流式，第一版仍不启用模型自主系统工具。
- Ollama通常不验证OpenAI兼容key，因此只绑定回环；客户端需要非空key时使用明确标注的本地占位值，不能宣称有服务端鉴权。
- 若需要局域网共享，新增受token保护的回环上游代理，限制来源；不直接把无鉴权11434开放给整个网络。
- 不需要WorkBuddy runner；可直接使用Ollama现有模型服务，避免额外复制CLI网关。

### L3：QQ切换与功能回归

- 停止笔记本相同账号的活动bot，PC扫码登录；先验证self_id，再由用户在测试群真实@。
- 重跑笔记本验收矩阵Q/P/V全部必要项：严格触发、上下文、完整/短链、无字幕ASR、故障说明。
- 确认B站请求以外没有模型推理/ASR数据发到云端；模型下载阶段有网络请求属于正常准备，不声称整个bot离线联网独立。
- 本地模型质量不达标时提交具体样例和A/B结果，不能把“接口通了”当成人设/总结质量通过。

### L4：运行和回滚

- PC启动顺序为Ollama→AstrBot→gate→NapCat；脚本检查端口、模型已安装和活动账号，手动启动优先。
- 按PC系统适配Start/Stop/Status，锁屏/睡眠/断网/GPU被其他任务占用分别测。
- 同样进行2小时混合工作负载观察；记录CPU/RAM/VRAM和失败率。
- 如需回笔记本：停PC bot、保留部署文件，再启动笔记本登录流程；不能靠两边抢登录实现自动故障转移。
