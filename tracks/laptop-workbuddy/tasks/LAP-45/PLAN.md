# LAP-45 七天运行日志保留方案

返回[交接](HANDOFF.md) / [PROGRESS](../../../../PROGRESS.md)。2026-10-31；本方案尚未实施，旧 worktree 清理已完成。

## 需求与非目标

运行日志按日轮转，保留当天和前六个自然日，自动清理更早的日志。每天从北京时间零点划分；日期过期后在下一轮维护清理，运行中检查间隔不超过一分钟，停机日志由每小时的本机维护任务清理。电脑关机时不能执行，开机/登录后补做。

仅处理本 SnowLuma 根的运行日志。配置、秘密、官方登录资料、AstrBot 会话库、群记忆、图库、state 任务/投递/清理台账、测试报告和历史验收证据不属于日志删除范围。不改模型、账号、额度、人设、触发规则、工具或媒体能力，不扩展到独立 WeChatbot 根、其他项目或全局日志目录。不新增日志大小限制；官方现有容量策略保留。

## 行为合同

1. 保留现有 `logs/model.log`、`gate.log`、`astrbot.log`、`intake-*.log` 和 `snowluma-startup.local.log` 作为当前日志入口；按日关闭/轮转到带 YYYY-MM-DD 日期的归档。常驻跨日、没有新输出时也要轮转/清理，不能只在重启或下一条消息时执行。
2. 使用标准库 TimedRotatingFileHandler，单个文件只有一个写入所有者；父进程不能继续长持同一个文件句柄。归档按日期过期，不能仅把 backupCount=7 当七天。保留当前日和前六日；只删除白名单中的闭合日志，失败跳过并下轮重试，不强删或重启服务。
3. process_host 的输出过滤原样保留，未通过 safe_line 的原文不能进入组件日志。官方控制台仍是本机私有原始日志，首次管理提示、版本检查错误与当前日志按钮继续可用；原文和凭据不能进入测试报告/Git。
4. 保留真实 Node/QQ 的原有创建身份。增加一个受管的控制台日志收集器：管理启动过程创建匿名管道，把写端交给官方进程，把读端仅传给收集器；Node/QQ 本身仍由原代码直接启动。用 Windows 标准句柄继承接口，仅放行指定 pipe handle，不能继承全部进程句柄。收集器单独登记 PID/create_time、固定组件和日志目的地，退出/启动失败/stop 均按创建身份回收；关闭 Node/QQ 写端后有界排空，再退出收集器。两个官方进程共用一个控制台日志写入者，不能由两个 handler 同时轮转同一文件。
5. 收集器/日志维护不监听端口、不收群消息、不读 QQ 账号资料、不调用模型/网络；不改变原生 QQ 启动窗口行为。收集器异常时报告明确日志故障，不能把它当 QQ 自身身份或按进程名清理。
6. `runtime/astrbot/bootstrap.local.log` 和 `configure-error.log` 若当前仍有写入入口，则统一改为本根按日运行日志；没有写入入口的现有遗留文件可按封闭清单/mtime 过期处理。不得递归猜测所有 *.log，特别不能删除 state 中的历史证据。
7. 停机后的到期删除由当前 Windows 用户的计划任务执行；任务只做封闭日志清理，不启动 bot。任务名固定 `QQbot-SnowLuma-LogRetention`，每小时及用户登录触发，错过执行后补做，禁止并行重叠实例，运行时限五分钟。机器关闭时无后台执行；下次可运行时补清。只管理本项目同名且 Action 精确匹配的任务，不改其他任务。
8. 删除前验证绝对路径、允许根、文件名及目录祖先，不跟随 junction/symlink；访问被拒或日志仍锁定则保留。只输出计数与错误类别，清理报告不记录日志正文、号码或秘密。

## 配置、默认值和生效

唯一用户配置入口仍是 `config/local`。在 `runtime.yaml` 增加 `logging`，同步分层 loader 的字段归属、旧单文件兼容和默认合并；不增加第二个用户配置源。

| 字段 | 默认值 | 合同 |
| --- | --- | --- |
| `logging.enabled` | true | 项目日志轮转和维护任务；false 关闭到期删除并撤销本项目维护任务，仍保留既有日志写入 |
| `logging.retention_days` | 7 | 正整数；按自然日保留；0/负数/布尔值拒绝，避免误变为永不清理或清空 |
| `logging.sweep_interval_minutes` | 60 | 正整数；停机维护任务频率；运行内轮转/检查固定每分钟 |

轮转 writer 使用本次受管实例的配置快照；修改后下次受管重启生效。维护任务由显式的安装/更新命令读取经过现有 loader 校验的当前本机配置，settings 更新后需运行同一幂等更新命令。缺文件/解释器/非法配置时不删除。Snow 原生 logRetainDays 继续用官方设置；本轮已是 7，无需为此重启或修改。

## 兼容、迁移与回滚

- 现有单一 .log 文件没有可验证的全量逐条时间信息。实施时受管停机后按原 mtime 归档为 legacy，记录文件数/字节；明确遗留文件到期日期，不伪称已经按每行时间精确裁切。可识别日期归档按日期直接过期，不解析/输出私密正文。七个自然日的完整保证从迁移完成后的新日志开始，legacy 最迟在其迁移日退出保留窗口时删除。
- 先完成离线检查，再备份必要的代码/本机配置和计划任务定义（只在忽略 state 内）；不复制一套运行环境或旧 worktree。代码/配置变化若影响当前视觉绑定，沿现有 LAP-43/44 当前版本试用流程做零生成检查和配对，不恢复旧大批验收门槛，不静默关闭识图。
- 回滚时先移除本项目维护任务/停用删除，按身份停止收集器和受管组件，恢复原启动接点/本机配置，按正常路径恢复运行。已删除的过期日志无法恢复；配置/会话/记忆/图库没有迁移或删除步骤。
- Git 只交付本任务代码/模板/说明/脱敏测试结果；本机配置、任务定义原件、管道句柄/身份、秘密、日志原文和生产备份不提交。普通 push 后核对实时远端 main；Git 交付与部署、真实 QQ/微信验收分别报告。

## 验证与验收

- 合成时钟：当天/第六日保留、第七日前归档过期；跨月/年及缺日归档仍按日期处理，静默跨日也维护。不得用真实等七天代替可重复的边界验证。
- 临时目录：只删除白名单闭合日志；状态库、记忆、配置、陌生文件、链接目标均保留；锁定/访问失败重试不强删，非法策略不删除。迁移大文件流式操作，报告没有原始内容。
- Windows 真实假子进程：同一受管收集器收两路合成输出，Node/QQ 替身身份保持，跨日可重新打开日志；失败/取消/停止后所有自建 pipe/收集器退出，无继承无关句柄，不触碰真实 QQ 或模型。
- 部署后：只读 health 8765/6200、现有 QQ/微信监听、router_ready、加载摘要、原配置保护检查；维护任务身份/Action/频率实际核对。用隔离合成日志验证计划任务实际入口，不人为老化或删除现有生产日志。
- 完成交付必须分别列出：已实现/离线通过/已启用与部署/计划任务实际入口通过；七天真实运行与真实消息效果未观察就保持未验证。
