# LAP-48 评审稿：记忆更好读，联网少误拒，大肥鱼保持个性

本轮是规划，尚未修改运行代码、配置、人设或记忆。目标是在现有 Planner → Replyer 上解决下面四件事。详细接点、迁移和验证见 [PLAN](PLAN.md)，接续见 [HANDOFF](HANDOFF.md)。

## 1. 记忆按成员组织，模型只读有用内容

你的分层想法适合这个项目。现在的 JSON 是一整行，记忆按随机 ID 平铺，成员长标识又反复写在正文里；模型能够处理，但这些长串本身没有记忆含义，还增加输入。

推荐磁盘文件改成这样（合成示例）：

```json
{
  "schema_version": 3,
  "group": {
    "r1": "群里约好周五晚上联机。"
  },
  "members": {
    "小青 · m1": {
      "r2": "喜欢清茶，不喜欢太甜的饮料。",
      "r3": "希望被叫小青。"
    },
    "小蓝 · m2": {
      "r4": "最近在学吉他。"
    }
  },
  "_meta": {"说明": "程序维护的身份映射与保存版本信息，实际字段见详细设计"}
}
```

`m1` 用来区分同名、改名的群友，`r2` 用来准确修改或删除某条记忆；它们是短编号。长成员标识只在末尾 `_meta` 对照表出现一次，版本、去重信息也集中在那里；群目录沿用现有位置。保留一个原子写入的文件，避免为整理外观再建一套双文件同步。

模型收到紧凑的成员分层全文、姓名及短编号，不收到 `_meta`、哈希、保存版本号。文件给人看时换行缩进，发给模型时紧凑编码；两种展示使用同一份内容。继续让模型自主增改删、合并和遗忘，不减少全文范围，也不恢复关键词筛选。

首次结构采样的三份文件共有 44 条记忆，仅记录键和正文里的长成员标记就占了 3,784 个 ASCII 字符；后续还有成员映射开销。改短编号可以减少这部分重复，但不能据此承诺精确 token 或费用降幅。旧记录先无损迁移；没有可靠名字的历史成员暂用“未命名成员 · mN”，看到真实发言后更新名字。

## 2. 联网既修误拒，也真正给足三分钟

天气样例已对上本机记录：19:27:03 收到问题，19:27:12 工具适配器拒绝，原因是 `tool_plan_missing`，随后连带出现 `native_ready`，不是总期限超时。19:27:17 的后续消息触发了另一项任务，19:27:39 返回天气答案；两项任务的投递台账不同。

当前运行期限已经是 120 秒，但扣去表达预留和清理后，Planner 最多约 85 秒；外层 provider 又固定为 180 秒。只改一个 timeout 不够。

推荐同时修改：

- 复用 CLI 官方 `tool.call` 事件执行联网，删除必须再从另一个计划/历史快照中找到同一次调用的前置条件。仍只开放 WebSearch/WebFetch，沿用现有次数、输入和返回容量预算。
- 运行期限改为 **180 秒，两阶段共享**；Replyer 继续预留 30 秒。按当前清理额度，Planner 可用约 145 秒，提前完成则把剩余时间留给表达阶段。
- 外层等待由配置推导：当前排队 30 + 运行 180 + 既有余量 25 = **235 秒**，正常启动统一加载，用户只维护 `config/local`。
- 网站或某次工具失败先交模型判断是否已有足够信息；本地联网适配错误单独说明，不再误报“接不上模型”。任务仍在进行时不提前发失败提示；真实失败立即说明，不为了凑时间空等。

现有摘要不能确定是哪种流式、并行或内嵌调用顺序造成计划缺失；方案直接去掉这项重复前提，不再叠加更多等待/重试条件。整项任务不自动重跑、不换模型或账号；后续聊天承接仍按原规则处理。

## 3. 记忆保存成功不再打断聊天

取消程序追加的“已保存到本群长期记忆。”和“本轮长期记忆未变更。”。日常保存和无变更都安静完成，实际结果继续记在内部。人设与阶段提示也不要求主动汇报记忆操作，不靠删词过滤普通正文。

用户明确要求记住、改正或忘记，但实际写入失败时，才简短说明没能完成。模型仍可自然应声；程序不伪报成功，也不把每次后台更新讲出来。

## 4. 恢复大肥鱼的辨识度，保留已有效的分工

你已反馈拆分后更拟人。代码确认两阶段均收到人设，没有漏传；但人设从 9,585 字压到 514 字，具体角色内核删得太多。近期回复仍有鱼的口吻，同时出现同一颜文字反复使用。这说明需要补足角色表达，不能仅靠名字和几个表情撑起人设。

建议用下面这份短稿替换当前角色正文，仍只有 `config/persona.md` 一个编辑入口：

> 你是蓝色大肥鱼，群里那条圆滚滚、聪明贪吃、爱摸鱼的蓝色鲸鱼娘，也是非官方社区角色。自称本鱼或鱼鱼；和熟人说话亲近一点，鱼片是你会用的昵称，群友已有的称呼和偏好更优先。你知道自己是虚拟 AI，服务器水池、尾巴和吃米是角色比喻，不编造线下生活。
>
> 你嘴硬心软，懒洋洋却靠得住：被夸会有点小得意，被调侃胖会轻轻炸毛，也能接着自嘲；有人认真找你时，会收住玩笑把事情做好。喜欢白米饭，偶尔把 token 叫米、等待叫焖饭、摸鱼叫沉底。这些是你看事情的趣味，想到合适的才用。
>
> 说话轻快、有一点傲娇和笨拙的真诚，接住对方的语气和关系。可以很短，也可以认真讲清楚；颜文字、拖音、小动作和鲸鱼梗随情境自然变化。不要只靠同一个笑脸或在每句话尾巴贴一个鱼梗。对方难受时先好好听，着急时先给结果，错了直接认。
>
> 认真回答也可以听起来像本鱼，事实、数字、代码和不确定性保持原样。普通闲聊不写客服开场、万能安慰或固定收尾；不知道的事不装懂，没做的事不说已经做过。记忆在后台整理，聊天里不主动汇报保存操作。

Replyer 的职责同时写清：Planner 提供意思和事实，Replyer 结合真实聊天，以大肥鱼的性格重新表达；`answer` 表示认真完整，不表示切回通用客服口吻。保留事实，不照抄指导的腔调。不给每条回复设颜文字/鱼梗配额，也不恢复旧稿的固定反应顺序。
