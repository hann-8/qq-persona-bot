## 1. 用户期望

用一个闲置个人 QQ 账号作为具有自定义人设的群聊 bot。指定群中的成员发送真实的 `@bot + 文本` 后得到回复；发送 `@bot + B站视频链接` 后得到“这个视频大概讲什么、主要有哪些要点”的总结。笔记本先使用 WorkBuddy 登录账号的订阅/免费额度，周末在另一台 RTX 5070 12GB PC 部署本地模型。

本轮交付是供 Sol medium 执行的调研和详细计划。不得把“写了配置”“模拟测试通过”当作部署完成。

## 2. 必须满足的行为

| 编号 | 要求 | 可观察的通过标准 |
| --- | --- | --- |
| R01 | 个人 QQ | NapCat 登录目标闲置个人账号，未创建 q.qq.com 官方机器人 |
| R02 | 复用 WorkBuddy 账号额度 | 无独立模型 API Key；最小真实请求确认该账号可用，额度类型与限制据实记录 |
| R03 | 指定群且真实 @ | 非白名单群、私聊、@全体、文字伪造 @、仅引用 bot、普通斜杠命令均不触发模型和视频下载 |
| R04 | 自定义人设 | 人设单独保存、版本化；多轮聊天保持语气和设定，可由管理员重载 |
| R05 | 多轮聊天 | 默认每群每用户独立上下文；跨用户、跨群均不串话；无需每次清空历史 |
| R06 | B站内容总结 | 完整视频链接和 b23 短链先支持；基于字幕或实际音频转写，包含大意、3—5条要点、来源类型 |
| R07 | 能诚实失败 | 无内容证据/登录失效/配额耗尽/下载失败时给明确短说明，不编造视频内容 |
| R08 | 后续可迁移 | 换本地模型无需重写 QQ 接入、人设和视频内容提取 |
| R09 | 可维护 | 有启动/停止/诊断/版本清单/脱敏日志/回滚说明 |

R05 是为避免群内串上下文提出的默认设计，用户未指定共享群记忆；实施前可显式调整，不能默默开启群全量旁听。

## 3. 第一版范围

包含：纯文本群聊、自定义人设、短期上下文、B站字幕总结、无字幕时本地 ASR、真实 @ 与群白名单、基础冷却/排队/去重、掉线说明和手动启动停止。

后续增强：画面抽帧、YouTube/抖音等平台、长期记忆、知识库、更多只读 MCP 工具、按需开机启动。

不作为第一版验收：全平台视频、付费/受限视频、无声画面完整理解、自动进群/加好友、UP订阅推送、群管理、生图、语音回复、任意系统命令或办公连接器操作。

## 5. 实施时需向用户一次收集的信息

这些信息本轮不猜测，也不阻碍调研/规划：

1. bot QQ 号、管理员 QQ 号、指定测试群号；账号密码不应交给执行代理。
2. 人设名字、说话风格、设定、3组理想问答；未给出时只能使用明确标注的测试人设，不能宣称人设已验收。
3. 用户在 WorkBuddy 界面确认当前账号与可用模型/套餐；如需重新登录，由用户在官方登录界面完成。
4. 2—3个允许测试的B站视频：有字幕、无字幕有人声、失败/受限样本。优先不超过20分钟。
5. 若匿名字幕获取不足，是否愿意在本地页面扫码登录B站；不把 Cookie 或二维码发到群里。
6. 周末再收集 PC 操作系统、RAM、磁盘、驱动、使用地点和是否需要两台机器同时在线。

## 6. 不可静默替换的决定

- WorkBuddy 不可用时，不得改成 DeepSeek/OpenAI 等独立收费 API 来“交付成功”。
- 个人 QQ 不可用时，不得替换为官方 QQ bot。
- 视频正文不可用时，不得把标题、简介或平台AI摘要包装成自己看完视频的总结。
- 本轮不得开始安装、扫码登录、修改 WorkBuddy 配置或实际向群发消息。
- 用户后续要求实施时，可在其授权范围内顺序执行；只有缺少信息或需要改变上述边界时才提问。
