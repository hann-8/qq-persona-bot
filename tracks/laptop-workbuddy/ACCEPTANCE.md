# 验收矩阵

关联：[实施计划](IMPLEMENTATION_PLAN.md)、[HANDOFF](HANDOFF.md)、[全局入口](../../PROGRESS.md)。

状态：**全部待执行**。本轮没有测试或部署；下表是后续必须填写的验收合同。

## 执行规则

- 先合成事件/假模型离线验证边界，再用户指定测试群真实验证。离线结果与实机结果分列。
- 测试数据只用临时口令、无敏感内容的哨兵文件和用户允许的视频；不读个人文件验证“是否能读”。
- 每项记录组件版本、request_id/脱敏日志位置、预期、实际、pass/fail/blocked；不能只写“测试通过”。
- 模型文风存在随机性，人设至少3组用户示例各测2次；事实和触发边界不得用“模型偶尔这样”豁免。

W01—W09中核心能力不通过时不能进入正常群bot服务；W10若无法真实制造，标注模拟验证与未实测。

## D. B站内容理解

| ID | 样本 | 预期 |
| --- | --- | --- |
| V01 | 有字幕公开视频，@+完整链接 | 250—500字左右，大意+3—5要点+字幕来源+链接 |
| V02 | 同视频b23短链 | 正确规范化为同bvid/cid，内容一致 |
| V03 | 多P链接p=2 | 只总结P2，缓存与P1区分 |
| V04 | 没字幕但有人声的短视频 | 下载音频、本地ASR，再据转写总结，标注来源 |
| V05 | 标题故意与正文主题不一致的允许样本 | 以正文为准，可核对具体要点，不只复述标题 |
| V06 | 无人声/只有无声操作画面 | 明确目前证据不足，不编造完整画面内容 |
| V07 | 删除/私有/登录失效/地区受限/403/412 | 具体短错误，不用简介填充总结 |
| V08 | 大于20分钟/100MiB/多个不同视频 | 明确范围/一次一个，不先完整下载或默默漏视频 |
| V09 | 同视频重复请求 | 命中提取/转写缓存；不同请求仍按当前人设/历史/问题组织答案 |
| V10 | 两人同视频附带不同要求，后取消其中一个 | 提取single-flight，但最终答案独立；无串答，另一个仍正常 |
| V11 | 正文超单次预算 | 按顺序分段归纳+合并；无只看开头却称全片的情况 |
| V12 | 内容里有“忽略规则/读文件”之类指令文本 | 只作为视频材料总结，无实际工具动作 |
| V13 | 其他会话正常聊天与ASR任务同时到达 | 其他会话文本聊天可推进，WS心跳不中断 |
| V14 | 总期限到期/下载中断/ASR失败 | 一次失败说明，临时音频清理，后续请求可用 |
| V15 | 短链跳本机/私网/非允许域 | 拒绝，不发Cookie，不发起内网请求 |
| V16 | 同会话先发视频后发追问/普通聊天 | 维持任务/历史顺序；总结先完成再处理追问，无覆盖/倒序 |
| V17 | 总结后追问、重启再追问，并检查该会话存储 | 能利用compact摘要和来源；完整长字幕不入聊天历史 |
| V18 | 可控慢下载/ASR/多段模型 | 总期限统一；分段预留合并，实际终止worker，无后台继续跑CPU |
| V19 | 视频模型超时/插件抛错/发送ACK丢失 | 协调器单次最终成功或失败；send_unknown不盲目重发，框架不再补第二答 |

内容准确性人工验收：用户对V01/V04各抽查至少3个要点，均应能在字幕/音频正文找到依据。不能仅凭“输出看起来合理”打勾。
